# Завершение оставшихся HTML-заглушек и юридический раздел

- Состояние: reviewed-awaiting-acceptance.
- Проверка: независимый ревизор, выбран пользователем.
- Исходный запрос: «так что у нас еще осталось как хтм прототип без функционала все исправляй.. ... подготовь страницы наших юридических страниц по стилю как нарисовали ... практический стандартизированный ... потом получим настоящие по API ... полноценные настоящие заглушки».
- Существующие изменения предыдущих задач не сбрасывать; commit/push/deploy не поручены. eBay только чтение при отдельной необходимости; оплаты/DHL/рассылки и новые внешние операции не активировать.

## Требования

- R1: инвентаризировать оставшиеся статические страницы и нерабочие элементы; отделить уже работающие от demo и определить проверяемую очередь исправлений.
- R2: сохранить согласованный HTML-дизайн, композицию/компоненты, общие токены, Django Templates и ключи локализации; исправить реальные назначения ссылок и пользовательские действия в выбранном объёме.
- R3: юридический раздел по reference: отдельные доступные без входа документы Impressum, Datenschutz, AGB, Widerruf/форма, Versand/Zahlung при необходимости. Полноценные немецкие черновики с явными неизвестными реквизитами, без вымышленных фирм/адресов/договорных обещаний и без заявления о юридической готовности.
- R4: переключение документов/TOC/печать/предлагаемые скачивания/футер ведут к правильному документу. Не имитировать скачивание PDF, если его нет. Тексты отделены от представления для будущего provider API, без небезопасного произвольного HTML. API сейчас не подключать.
- R5: показывать фактическую обработку данных текущим приложением и отделять будущие Stripe/DHL/аналитику от активного поведения. Необязательные согласия не включать, не придумывать сроки хранения/реальные гарантии. Проверить актуальные официальные источники немецких требований.
- R6: целевые тесты, Django/migration/lint проверки по затронутому коду, desktop/mobile browser и независимый ревизор; честно зафиксировать оставшиеся ограничения.

## Уточнения

- Пользователь выбрал независимого ревизора.
- Пользователь включил настоящую локальную корзину и сохранение тестового заказа. Серверные суммы/валидация/CSRF, отсутствие мутаций GET, персональные заказы без утечек и защита от повторного submit входят в реализацию. Реальные оплаты, резерв реального eBay-остатка, DHL и реальные письма клиентам не разрешены.
- R7: локальная корзина по Variant/SKU, добавление/количество/удаление, Decimal/server pricing, сессии и проверка доступности; дизайн reference сохраняется, пустое состояние настоящее.
- R8: гостевой/авторизованный checkout с валидацией адреса, серверным review и сохранением явно тестового заказа со snapshot строк/цен/адреса; повторный submit не создаёт дубликат. Confirmation/customer orderlist/detail показывают соответствующие реальные local test orders с object-level access; не показывать фиктивный tracking/успешную оплату. - R9 (декомпозиция исходного «всё исправляй», не новое внешнее разрешение): локальное избранное и сохранение контактного обращения вместо ложного успеха/disabled заглушки. Без реальной доставки письма; стандартный доступ staff к обращениям, явные цели/ограничения/минимизация данных. Пока будущие Stripe/DHL/возвраты/клуб/рекламные кампании не активируются.

## План

1. Инвентаризация маршрутов, demo JS/actions и reference; составить конкретные исправления.
2. Юридическая фича: черновики, стабильные URL/контекст, reference reader, локализация, навигация/печать.
3. Исправления остальных заглушек по выявленному списку и выбранному объёму; финансовые/внешние действия остаются безопасными.
4. Интеграция, автоматические и browser проверки, независимая ревизия и проверка итоговых утверждений.
