# Koongo: возможности и ограничения

Проверено по публичным официальным источникам 11.10.2026. Аккаунт, STRATO-пакет и индивидуальные условия не проверялись; интеграции не включались.

## Что умеет

| Функция | Подтверждение и применимость |
|---|---|
| Товары на маркетплейсах | Создание товаров/предложений, обновление цен и количества через Marketplace Manager |
| Существующий eBay | Отдельный wizard Update Price & Inventory: только остаток, только цена или оба поля; исключённое поле остаётся без изменения |
| Правила каналов | Фильтры товаров, сопоставление категорий/атрибутов, преобразования данных, разные цены для площадок |
| Заказы | Импорт заказов eBay/Amazon в поддерживаемый магазин; обработка вместе с заказами сайта |
| Отправка | Передача tracking обратно на площадку |
| Ошибки | Статусы синхронизации, история команд, просмотр проблемных заказов; инструменты исправления и повторного импорта |
| Feeds | Генерация файлов для рекламных/товарных каналов; сам feed-модуль не включает управление заказами |
| MCP | Настройка интеграций, mapping, просмотр сводки/ошибок и запуск синхронизации через ассистента |

Источники: [Marketplace Manager](https://help.koongo.com/en/articles/13746032-new-marketplace-manager), [eBay stock-only](https://help.koongo.com/en/articles/11525673-update-price-and-inventory-on-ebay), [заказы и tracking](https://help.koongo.com/en/articles/8582844-which-marketplaces-and-platforms-does-koongo-support-at-order-level), [правила и цены Amazon](https://www.koongo.com/channels/amazon/), [MCP orders](https://help.koongo.com/en/articles/16543948-manage-orders-order-connections).

Возвраты/RMA/refunds представлены в модели заказов Koongo, но поддержка зависит от конкретной пары площадка–магазин. Полную автоматизацию отмен, частичных возвратов и возврата денег для eBay/Amazon + Django публичные страницы не подтвердили. Наличие вкладки Refunds не означает универсальное выполнение возврата. [Order details](https://help.koongo.com/en/articles/8582847-order-details-explained).

## Существующие объявления eBay

Для нас перспективен режим **Stock only**: сохраняем объявления и их цены, передаём количество по согласованным идентификаторам. Koongo требует проверить используемые SKU. При нулевом остатке/исключении продукта документация обещает деактивацию; точное действие на нашем типе listings нужно проверить до включения AUTO. [Wizard](https://help.koongo.com/en/articles/11525673-update-price-and-inventory-on-ebay).

Не подтверждено, что Koongo автоматически выгрузит весь существующий eBay-магазин в новый Django-каталог. Документированный custom путь начинается с каталога нашего магазина. Импорт исходных listings, фотографии, вариации, одинаковые SKU в нескольких объявлениях и сохранение item ID требуют отдельной проверки.

## Скорость и двойные продажи

Koongo указывает интервалы в зависимости от плана/интеграции: общая страница — 5/15/60 минут; страница Amazon — 5/15/30 минут. FAQ говорит о частоте до 5 минут на Pro. Это не единая гарантия задержки для custom Django + eBay. [Общий сервис](https://www.koongo.com/), [Amazon](https://www.koongo.com/channels/amazon/), [FAQ](https://www.koongo.com/faq/).

Для custom магазина есть отдельный **Import Interval** получения товарного feed. Поэтому фактическая задержка может складываться из получения данных магазина, обработки Koongo и обновления площадки. Нельзя считать рекламные «5 минут» гарантированным временем от покупки до изменения другого канала. [Custom settings](https://help.koongo.com/en/articles/8582736-koongo-settings-for-custom-platforms).

Koongo снижает вероятность перепродажи, но не обеспечивает атомарный общий резерв между двумя checkout. В их собственной справке причиной out-of-stock ошибки назван одновременный заказ одного товара в нескольких местах. Это подтверждает существование риска даже при использовании сервиса. [Описание ошибки](https://help.koongo.com/en/articles/8582893-rma-order-errors).

При около 100 продажах/месяц достаточно начать с синхронизации, наблюдения ошибок и сверки заказов. Не обещаем математический нулевой риск; дополнительные ограничения последних единиц вводим по фактическим проблемам.

## Подключение Django

1. Каталог: URL стандартного Google Shopping feed; значения SKU/EAN, размера/цвета и количества должны соответствовать объявлениям.
2. Заказы: собственная интеграция с Koongo Order API. Спецификацию и требования Koongo предлагает получить у поддержки.
3. В магазине: импорт заказа с защитой от дублей, изменение остатков, статусы отправки/tracking, наблюдение ошибок и сверка.

Источники: [Custom platform feed](https://help.koongo.com/en/collections/6939287-connect-your-store), [Custom Order API](https://help.koongo.com/en/articles/8582844-which-marketplaces-and-platforms-does-koongo-support-at-order-level).

Направление HTTP-вызовов Order API, webhooks, авторизация, повторы и поддержка событий пока неизвестны: публичного контракта недостаточно. Python SDK в проверенных материалах не найден; после получения спецификации выбираем httpx-клиент и/или входящие Django endpoints. MCP помогает оператору управлять Koongo, но не заменяет постоянную интеграцию сайта.

## Тарифы

Публичная новая модель:

- Marketplace Starter: от **€69/месяц**, 1 магазин, 1000 продуктов, 100 заказов; дополнительная площадка €30/месяц.
- Feeds: €24/месяц за 5 feeds — это другой модуль.
- Вариант товара считается отдельным SKU/продуктом: 200 моделей × 5 размеров × 3 цвета могут дать 3000 позиций.
- Дополнительные объёмы/функции оплачиваются отдельно; есть автоматическая корректировка тарифа по ресурсам.
- Free: ограниченный тестовый план; для платного плана указан 7-дневный trial.

Источники: [модули](https://help.koongo.com/en/articles/13746113-koongo-modular-pricing), [лимиты Starter](https://help.koongo.com/en/articles/13746032-new-marketplace-manager), [подсчёт SKU и billing](https://help.koongo.com/en/articles/8582904-how-do-i-modify-my-koongo-subscription).

Это не цена пакета STRATO. Legacy/партнёрские тарифы могут отличаться. Для решения нужны расчёт конкретного аккаунта, НДС и стоимость нужной частоты/двух площадок; новые подписки не оформлены.

## Вопросы поддержке перед выбором

1. Предоставьте актуальную спецификацию custom Order API: авторизация, направления вызовов, webhooks/опрос, повторы и дедупликация.
2. Можно ли обновлять только stock существующих eBay DE listings без пересоздания? Какие идентификаторы и типы listings поддерживаются?
3. Можно ли импортировать исходный каталог с eBay? Как обрабатываются вариации и несколько listings одного SKU?
4. Какова фактическая задержка «покупка на сайте → eBay» и обратно для custom platform? Есть ли немедленная отправка остатков вместо ожидания feed?
5. Что происходит при quantity=0: скрытие, завершение listing, возможность восстановления и сохранение item ID?
6. Какие отмены, refunds/RMA и tracking поддерживаются именно для eBay/Amazon + custom platform?
7. Как обнаружить пропущенный заказ/ошибку, выполнить сверку и получить уведомление об остановке синхронизации?
8. Какой тариф нужен для наших SKU, примерно 100 заказов и eBay; сколько добавит Amazon? Есть ли условия STRATO, применимые к собственному магазину?

## Предварительное решение

Koongo закрывает заметную часть управления несколькими площадками: форматы товаров, правила, публикации, импорт заказов и tracking. Для одного действующего eBay-магазина сначала проверяем Stock only + custom Order API и стоимость. Выбор между Koongo и прямым eBay API делаем после получения контракта; подключение Django не считается готовым только на основании рекламной страницы.
