# Каталог, прямая синхронизация eBay и фотографии

Согласованные требования от 13.10.2026. Документ описывает будущую реализацию; код интеграции и импорт ещё не выполнены.

## Прямая синхронизация остатков

Основной вариант прототипа — собственный адаптер eBay API. Задача: согласовать **доступное количество каждого варианта**, а не число заказов. Полный импорт заказов eBay, персональных данных покупателей и управление их доставкой не входят в начальный объём.

- Покупка на сайте учитывается локально; новое доступное количество отправляется в связанное объявление eBay.
- Продажи и изменения на eBay учитываются при сверке соответствующих вариантов сайта.
- До подтверждения исходящего обновления нельзя безусловно перезаписывать локальный остаток старым снимком eBay.
- Храним состояние синхронизации, ожидающие изменения и ошибки; предусмотрена повторная сверка.
- Источник истины, правила ручной правки, резервирования и отмен определяем до включения продаж. Если количества недостаточно, чтобы отличить продажу от собственного обновления/ручной правки, получаем минимальные данные событий или строк продаж без создания полноценных заказов в магазине.
- Один webhook/повторный ответ не должен дважды уменьшать количество. Для последней единицы остаётся риск одновременной покупки в двух каналах; сложную защиту на старте не вводим без необходимости.

Опрос каждые 10 секунд — возможный режим после проверки квот и методов, не обязательная настройка и не гарантия задержки данных eBay. Обновления отправляем по изменениям; каталог целиком на каждом цикле не скачиваем. Тип объявления определяет применимый API. Существующие объявления не пересоздаём и не переводим в другую API-модель автоматически.

## Одна карточка, несколько вариантов

Около 12 отдельных позиций eBay могут быть представлены одной карточкой сайта. Объявления eBay при этом сохраняются.

| Сущность | Данные |
|---|---|
| Товар | Бренд, модель/артикул, общие название и описание |
| Вариант | Цвет, размер, SKU/EAN, цена, доступное количество и условия доставки |
| Связь с eBay | Наш вариант → item ID и идентификатор вариации, если объявление содержит вариации |
| Галерея цвета | Фотографии модели в конкретном цвете, порядок и главное изображение |

Связь объявлений храним отдельно от карточки. Если одному варианту соответствуют несколько listings, их количество нельзя просто суммировать: сначала проверяем, представляют ли они один физический запас.

Поведение карточки:

1. Выбор цвета переключает главное фото и галерею, если фотографии этого цвета доступны.
2. Показываем размеры выбранного цвета и наличие конкретных вариантов.
3. Выбор размера обновляет цену, наличие и срок доставки; неподтверждённые сроки не обещаем.
4. В корзину добавляется конкретный SKU, а не только общий товар.
5. Если фото цвета нет, используем общее изображение с явно указанным выбранным цветом; автоматически перекрашивать фото не требуется.

## Импорт фото по сортировке шефа

По информации пользователя есть примерно 30 ГБ качественных PNG производителя. Шеф уже сортирует фотографии артикулов, выставленных на eBay. Используем эту структуру как основу импорта; массовая повторная сортировка заранее не требуется.

Перед реализацией смотрим небольшой пример папок и имён файлов. Если присутствуют артикул модели и код цвета, используем их для автоматического сопоставления. Формат имён пока не известен — не закрепляем выдуманное правило.

Процесс импорта:

1. Инвентаризация файлов без изменения оригиналов, извлечение известных идентификаторов.
2. Предварительный отчёт: найденный товар/цвет, уверенное совпадение, неоднозначность или отсутствие соответствия.
3. Проверка спорных связей в админке; автоматическое сопоставление только по достаточным признакам.
4. Сохранение исходников и привязка галереи к цвету модели. Размеры используют общие фотографии цвета без повторного хранения.
5. Фоновая генерация размеров для каталога, карточки и увеличения в WebP/AVIF при поддержке кодеков.
6. Повторный импорт распознаёт уже обработанные файлы, не создаёт дубликаты и сохраняет ручные исправления привязки.

Исходники сохраняем отдельно от веб-версий в хранилище. Браузер получает подходящий размер изображения, а не исходный PNG из всего архива. Конкретную структуру S3 и параметры преобразования определим по реальным фотографиям.
