# Datenschutz и юридические интеграции

Предварительные кандидаты, проверено 11.10.2026. Готовой библиотеки «установил — магазин соответствует всем требованиям» нет: юридические тексты, согласия, доступ и хранение данных решают разные задачи.

## Юридические тексты

**Первый кандидат — IT-Recht Kanzlei.** Официально предусмотрена интеграция собственных магазинов. Магазин генерирует токен, его регистрируют в клиентском портале, далее тексты передаются и обновляются. Спецификация доступна клиентам; официальный Python SDK не подтверждён. До покупки уточнить подходящий пакет и доступ к интерфейсу. [In-house shops](https://www.it-recht-kanzlei.de/rechtstexte-schnittstelle-inhouse-individual-shops.html), [доступ к спецификации](https://www.it-recht-kanzlei.de/Portal/muster.php?_rid=308).

**Альтернатива — Händlerbund.** Есть публичная спецификация получения документов с токеном магазина. Имя PDF содержит 2018: актуальность протокола нужно подтвердить. Лицензия зависит от договора и указанного магазина; анкета должна соответствовать реальной работе сайта. [API PDF](https://hb.haendlerbund.de/hubfs/Dokumentation%20AGB%20Schnittstelle_2018_08.pdf), [условия договора](https://marketplace.haendlerbund.de/pages/agb-mitgliedschaften).

Адаптер зависит от направления API: для IT-Recht может понадобиться входящий endpoint, для получения текстов — HTTP-клиент. Тексты сохраняем локально с датой, версией и статусом обновления; при сбое показываем последнюю действующую версию и уведомляем администратора. Конкретный список страниц и формулировки определяются пакетом и устройством магазина, а не фиксированным числом файлов.

## Cookie consent

**django-cookie-consent** — кандидат для Django Templates: группы cookies, opt-in, журнал выбора и проверки в шаблонах/Python. Current main заявляет Django 5.2/6.0 и Python ≥3.10; совместимость выбранного релиза проверяем при установке. Пакет не блокирует автоматически все сторонние скрипты: аналитику и другие необязательные подключения связываем с согласием сами. [Документация](https://django-cookie-consent.readthedocs.io/en/latest/), [JavaScript hooks](https://django-cookie-consent.readthedocs.io/en/latest/javascript.html), [заявленная совместимость](https://github.com/django-commons/django-cookie-consent/blob/main/pyproject.toml).

Нужный механизм согласия определяем по фактическим технологиям сайта. Не добавляем tracking только ради использования баннера. [Разъяснения по cookies, Datenschutz Hessen](https://datenschutz.hessen.de/datenschutz/internet-und-medien/haeufige-fragen-zu-cookies).

`django-gdpr-assist` не включаем в новый стек: репозиторий архивирован. [Репозиторий](https://github.com/wildfish/django-gdpr-assist).

## Работа с персональными данными

Небольшой собственный модуль должен знать реальные модели магазина:

- Экспорт данных покупателя: профиль, адреса, заказы и согласия.
- Удаление/обезличивание по правилам хранения; нельзя безусловно удалять все документы заказа.
- Разделение прав клиента и сотрудников, минимизация записываемых данных и журналов.
- Отдельное согласие для рекламной рассылки; адрес из заказа сам по себе не создаёт подписку.
- Реестр используемых провайдеров, сроков хранения и договоров обработки данных по применимости.

Юридический сервис готовит и обновляет тексты на основании фактов о магазине. Он не настраивает наши права доступа, резервные копии, отправку данных и удаление записей. Для договоров обработки данных есть официальные материалы BfDI; роли конкретных провайдеров проверяем отдельно. [Материал BfDI](https://www.bfdi.bund.de/SharedDocs/Downloads/DE/Muster/Muster_zur_Auftragsverarbeitung.pdf?__blob=publicationFile&v=2).

Для прототипа используем вымышленные данные. Перед запуском согласовываем с юридическим провайдером фактический checkout, способы оплаты, доставку, рассылку и подключённые технологии.
