# Рабочий кабинет — 16.10.2026

План: [staff-cabinet-plan.md](staff-cabinet-plan.md). Реализованы каркас, общий быстрый доступ, список моделей и редакторы модели/вариантов. Галереи, импорт, публикация, EAN, автоматические SKU и генерация матрицы по цветам×размерам пока не реализованы.

## Вход и маршруты

- `/staff/` — рабочий стол.
- `/accounts/login/` — единый вход покупателей и сотрудников. `/staff/login/` перенаправляет туда; отдельного пароля кабинета нет. Active staff/superuser дополнительно проходит обязательный MFA; см. [identity-and-mfa.md](identity-and-mfa.md).
- `/staff/catalog/` — список, поиск по модели/бренду/SKU, фильтры бренда/категории, пагинация 24.
- `/staff/catalog/new/` — создать черновик.
- `/staff/catalog/<pk>/` — основные данные.
- `/staff/catalog/<pk>/variants/` — варианты, новые строки без промежуточного сохранения, максимум 100.
- `/staff/catalog/settings/` — пока read-only описание правил раздела.
- `/staff/settings/` — общий быстрый доступ.
- `/staff/logout/confirm/` — подтверждение; выход только POST `/staff/logout/` с CSRF.

Нужна Django-учётная запись is_staff. Первую owner-запись можно создать локально: `.venv/Scripts/python.exe tools/manage_local.py createsuperuser`; пароль вводится интерактивно, не хранится в репозитории. Временный browser-test пользователь удалён, постоянные пароли не задавались.

## Подключение библиотеки

web.staff.cabinet использует существующий codex registry. Верхние группы Shop/Verwaltung, sidebar выбранного модуля, закреплённый блок настроек снизу. Быстрые ссылки — библиотечные quick_access helpers и зарегистрированные sidebar items.

CabinetPreferences.quick_access_keys — общая настройка навигации, не универсальный JSON настроек/секретов. Персональных закреплений нет. Ключи библиотеки зависят от module/order/position: не переставлять существующие объявления меню без проверки закреплений.

Проектный context processor использует library runtime/registry, проверяет права и не создаёт настройки на GET. Generic library settings URLs не открыты: их дефолтный доступ и singleton creation на чтении не подходят этому этапу. Тема в static/cabinet/css/app_cabinet.css, staff/base наследует библиотечную оболочку; библиотечные исходники не изменены.

## Данные и защита сохранения

Основная форма: бренд, категория, модель, отдельный manufacturer_article, slug, теги, существующий ключ описания. Новая модель всегда черновик; публикация disabled и не меняется POST-запросом.

Варианты: SKU/цвет/размер/цена/валюта/активность/demo-количество. Существующий SKU неизменяемый. Нельзя подставить чужой ID, продублировать SKU/сочетание, смешать валюты, выключить последний активный вариант опубликованной модели или добавить строки без права add. SKU новых вариантов пока вводятся вручную. Ключи описаний/цветов остаются техническими полями: удобный редактор локализованных текстов и справочники — следующий UX-этап.

Обе формы блокируют Product через select_for_update и проверяют подписанный снимок. Сохранение транзакционное; stale форма не перетирает новые данные. Ошибки уникальности возвращаются формой без traceback. Функциональные сценарии проверены; отдельного конкурентного PostgreSQL stress-теста ещё нет.

StaffAuditEvent хранит actor/action/object/time в той же транзакции, без POST-дампов, паролей и секретов. UI истории, production retention и очистка — отдельные задачи до production. Рекламных SDK/событий нет; localStorage хранит состояние панели как функциональную настройку, не аналитику.

## Права

- Active staff/superuser обязателен; customer с model permission всё равно не входит.
- Список/настройки каталога: catalog.view_product.
- Модель: catalog.add_product либо catalog.change_product соответственно.
- Варианты: catalog.change_product и catalog.change_productvariant; новые строки дополнительно catalog.add_productvariant.
- Общие настройки: staff.change_cabinetpreferences.

Проверки выполняются endpoint, а не только меню. CSRF, чужие ID, поддельные quick-access keys, stale формы и раздельные права покрыты тестами.

Количества — demo_quantity, не настоящий склад/резервы/eBay sync. Оплаты, DHL, письма и запись в eBay не запускались. Публикация, копирование модели, фото, реальные остатки и сохранённые фильтры/сортировка остаются в очереди.
