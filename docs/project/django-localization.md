# Ключи текстов и Django gettext

Реализовано 15.10.2026. App `web.localization`, template library `shop_i18n`.

```django
{% load shop_i18n %}
{% text 'home.hero.title.first' %}
{% text 'common.greeting' name=customer_name %}
```

Немецкие значения хранятся в `src/web/localization/messages/de.json`, а шаблоны ссылаются на стабильные ключи. При отсутствии перевода язык откатывается к немецкому, неизвестный ключ выводится как `[key]` для диагностики. Интерполяция именованными `{name}`, escaping Django не отключается. Бренды, артикулы, цены и данные покупателя не являются переводимыми интерфейсными строками.

Обычные блоки, подписи, placeholders, alt/aria-label и основные интерактивные сообщения перенесены в каталог. Семантические ключи используются для общей навигации/hero; импортированные блоки имеют namespace фичи/страницы и устойчивый hash текста, чтобы перенос блока не менял ключ. При изменении формулировки существующей фичи сохраняем её ключ и обновляем значение, не генерируем новый ключ без необходимости. При ручном развитии компонента предпочтительны читаемые смысловые ключи.

`translate_text(key, **params)` использует Django gettext. `python tools/compile_shop_messages.py` создаёт совместимые `locale/<lang>/LC_MESSAGES/django.po` и `django.mo` из JSON без системного GNU gettext. Для русского добавляется `messages/ru.json` с теми же ключами; полный русский перевод витрины ещё не выполнен; staff.* переведён полностью для рабочего кабинета. Компиляция и перезапуск Django нужны после изменения каталогов.

LocaleMiddleware и i18n URLs включены: немецкий по умолчанию без префикса, русский `/ru/` пока с немецким fallback. JavaScript получает от Django безопасный `json_script` словарь нужной страницы и использует `window.shopText(key)`; при HTML-вставке обязательно escaping. Не писать переведённый HTML через mark_safe и не включать пользовательские данные в исходные каталоги.

Импорт источника: `python tools/import_storefront_templates.py`. Он читает согласованный `docs/prototype`, создаёт шаблоны в фичах, общий каркас/ресурсы и ключи. Не выполняется при HTTP-запросах. Повторный импорт перезаписывает сгенерированные шаблоны: после ручного развития фич не запускать его вслепую; сначала сравнить изменения источника и сохранить ручные доработки. Каталог переводов сохраняет существующие записи, не удаляет старые автоматически.

22.10.2026: staff включён в i18n_patterns: русский `/ru/staff/`, немецкий `/staff/`. Переключатель кабинета использует локализованный Django set_language endpoint: `/ru/i18n/setlang/` или `/i18n/setlang/`; так Django разрешает исходный URL в его текущем языке перед переводом. Нельзя потерять locale при POST redirect/навигации. Полноту staff.* и параметры переводов проверяет test_staff_localization.py.
