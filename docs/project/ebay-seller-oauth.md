# Авторизация продавца eBay

Статус 16.10.2026: фича реализована; приёмка на HTTPS-стенде фиксируется ниже. Текущий токен личного аккаунта `prime_8088` не открыл товары `sonne_fuer_alle`; командный доступ в браузере не заменяет авторизацию продавца. Владелец входит сам на eBay, пароль и MFA магазину не передаются.

## Действия в Developer Portal

Production → User Tokens → существующий RuName, OAuth Enabled:

- Display Title: `Maennermasche Shop`.
- Your auth accepted URL: `https://shop.pinlite.dev/integrations/ebay/oauth/callback/`.
- Your auth declined URL: тот же `https://shop.pinlite.dev/integrations/ebay/oauth/callback/`.
- Сохранить. Callback уведомления об удалении аккаунта оставляется отдельным и не меняется.

RuName из портала должен точно совпадать с `EBAY_OAUTH_RUNAME`. Публикация обработчика на сервере не меняет настройки портала автоматически. Privacy Policy URL должен вести на действительную доступную политику приложения; нельзя подменять её чужой политикой или объявлять иллюстративный юридический текст утверждённым.

Одноразовая ссылка создаётся оператором отдельно для ожидаемого продавца. Секрет приглашения не помещается в Git, публичную документацию или журналы. После подтверждения на нашей странице продавец перенаправляется на фиксированный официальный eBay OAuth endpoint; после возврата сервер проверяет state, cookie браузера и пользователя через GetUser. Другой аккаунт отклоняется; сохранение токенов допускается только для ожидаемого продавца.

## Права и границы

Фиксированный запрос: `api_scope`, `sell.inventory.readonly`, `sell.listing.read`, `sell.fulfillment.readonly`, `commerce.notification.subscription` (с префиксом `https://api.ebay.com/oauth/`). Последнее разрешение предназначено для настройки доставки уведомлений, а не изменения объявлений или заказов. Базовый Trading scope шире режима чтения: его название не гарантирует запрет записей. Отдельный allowlist транспорта ограничивает реализованные вызовы; универсального клиента записи нет.

В этой фиче внешние действия — только OAuth token exchange и GetUser для проверки владельца. Подключение продавца не запускает импорт, изменение остатков, обработку оплаты, отгрузку или создание подписки. Наличие refresh token не означает реализованный планировщик обновления и чтения заказов.

## Продажи и webhooks — следующий этап

Владелец запросил наблюдение за настоящими продажами eBay. Уведомление `ORDER_CONFIRMATION` предусмотрено Notification API. Сначала прочитать метаданные доступного topic/scopes, затем подключить отдельный destination и seller subscription; не использовать обработчик удаления аккаунта для заказов. Проверить подпись, получателя, повторы и идентификаторы; после события сверять факты читающим API. Периодическая сверка нужна для пропущенных и поздних событий. Не вычитать количество дважды при webhook + polling.

Сохранять минимальные ID события/заказа/строки/объявления, количество и статус; не импортировать адреса покупателей или полные заказы ради сверки запасов. Нельзя автоматически считать завершённым оформлением любой неоплаченный заказ. Не создавать реальные покупки, возвраты или отправки ради теста; использовать синтетические события и отдельный eBay Sandbox.

Доступность ORDER_CONFIRMATION для приложения и достаточно ли readonly scope проверить через getTopic/getTopics; расширение до пишущего `sell.fulfillment` не допускается автоматически.

## Данные и безопасность

- Приглашение — ограниченная по времени capability, в БД только hash; state одноразовый и привязан к HttpOnly/Secure cookie браузера. GET приглашения не авторизует продавца без явного POST с CSRF.
- Access/refresh tokens шифруются отдельными Fernet keys `EBAY_OAUTH_ENCRYPTION_KEYS`, не MFA-ключом. Ключ хранить приватно и резервировать отдельно от БД; не печатать токены и ответы провайдера.
- Callback и invitation path не пишутся в Nginx access/error logs, Gunicorn access log выключен. Ответы private/no-store/noindex. Результат показывается на чистом URL без code/state.
- OAuth — операционная авторизация интеграции, а не marketing opt-in. Необязательная аналитика на этих страницах выключена. Временная cookie служит защите авторизации и удаляется при завершении/истекает; журналы не содержат личных данных.
- До импорта данных заказов требуется реализованный жизненный цикл удаления данных eBay. Текущий deletion receipt `review_required` сам по себе не выполняет удаление; не заявлять полное compliance по одному успешному тестовому уведомлению.
- Очистка: `python manage.py cleanup_ebay_oauth` удаляет истёкшие приглашения и попытки. Автоматическое расписание пока не включено; оператор выполняет команду после проверки и не реже следующего рабочего дня. Попытки действуют 10 минут, ссылка 24 часа; cookie 10 минут. Сами токены сохраняются на время подключённой интеграции, но до запуска фонового чтения нужны отдельная процедура отключения/удаления и проверка отзыва на eBay. Очистка приглашений не удаляет SellerConnection. Необязательная история действий не собирается.

## Проверки реализации

`tests/web/test_ebay_oauth.py`: 33 offline проверки успешного обмена, неверного продавца, CSRF, state/cookie/expiry/replay, шифрования, минимального транспорта и очистки. Общий набор после интеграции: 305 тестов прошли; Ruff чистый, пропущенных миграций нет. Внешний adapter разрешает только token exchange и фиксированное XML-тело GetUser, включая запрет подмены тела при читающем заголовке. Автоматическое обновление токенов, polling продаж и реальная подписка не реализованы этой фичей.
