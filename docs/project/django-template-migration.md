# Перенос согласованного прототипа в Django

План реализации от 15.10.2026, разрешён владельцем. Источник внешнего вида — docs/prototype; исходный статический вариант и GitHub Pages сохраняются.

1. Проверить foundation, настройки БД и существующие контейнеры. Не объявлять настроенный Postgres работающим до проверки подключения и миграций.
2. Ввести локализацию стабильными ключами: namespace фичи/блока, немецкий каталог, Django gettext. Шаблоны содержат ключи, не немецкие msgid; модели хранят ключи описаний/подписей, имена брендов/SKU не переводятся. Перевод не пишется HTML-разметкой и не отключает escaping.
3. Перенести все страницы в namespaces фич, выделить общий base/header/footer и static. Сохранить внешний вид, фотографии, модальные окна, состояния и скрипты. URL — именованные Django routes. Общий каркас не загружается из файлов статического прототипа во время запроса.
4. Создать необходимые модели каталога/вариантов/галерей/тегов, корзины, снимков заказа и попыток оплаты/возмещения с миграциями. Источник интерфейса сначала явные presentation-моки; не выдавать их за реальные платежи или остатки.
5. Страницы подключить к локальным demo contexts. Для моделей — идемпотентное заполнение демонстрационными товарами. Payment UI показывает выбранные Stripe/PayPal, но реальный Stripe sandbox пока не подключается: synthetic demo и настоящий API sandbox различаются.
6. Проверить маршруты, рендеринг/локализацию/escaping, модели и seed, ограничения мутаций, отсутствие внешних финансовых вызовов. Открыть desktop/mobile в браузере, проверить переходы и исходные компоненты.

Пока не реализуем финансовое исполнение, реальные заказы/письма/DHL/eBay, рекламное отслеживание. Публичные auth/account формы — демонстрационные и не должны собирать реальные пароли или создавать ложное впечатление успешной регистрации. Проверенные механизмы Django подключаются при реализации настоящей авторизации.

## Выполнено

Обновление 16.10.2026: главная и PDP уже подключены к ORM и независимому выбору варианта, 106 тестов. Остальные страницы и редакционные блоки остаются demo. Актуальные точки входа и ограничения — [catalog-read-api.md](catalog-read-api.md); описание первоначального переноса ниже относится к этапу 15.10.

30 страниц перенесены в `src/web/<feature>/templates/<feature>/`; base/header/footer общие. Фичи catalog, cart, orders, payments, customer, support подключены именованными routes. Фотографии/шрифты источника пока внешние; JS/CSS/логотипы обслуживаются через Django static. Локализация: [контракт ключей](django-localization.md).

Созданы 12 ORM-моделей: 6 каталога (включая теги и цветовые галереи), 2 корзины, 2 заказа, попытка платежа и попытка возврата. Это persistence-основа без финансовых переходов, резервов и суммарных проверок refunds. Приёмка последних потребует отдельных транзакционных сервисов. PostgreSQL магазина поднят отдельно, начальные миграции применены; seed создаёт 4 товара/32 условных варианта. Витрина использует presentation-моки; подключение selectors вместо моков — следующий этап. Главная и суммы/строки заказа уже получают значения через контекст.

`PaymentAttempt.mode` допускает demo/sandbox и блокирует live, однако наличие записи sandbox не выполняет API-вызов. Синтетическая демонстрация не называется настоящим Stripe sandbox. GET экранов не создаёт записи и не вызывает интеграции; POST не реализован (405 либо отказ CSRF).

Локальный запуск из virtualenv с `.env` текущего checkout:

```powershell
docker compose --env-file .env -f deploy/compose.yml -f deploy/compose.local-db.yml up -d postgres redis
.venv/Scripts/python.exe tools/manage_local.py migrate
.venv/Scripts/python.exe tools/manage_local.py seed_demo_catalog
.venv/Scripts/python.exe tools/manage_local.py runserver 127.0.0.1:8030 --noreload
```

Дополнительный compose публикует только loopback: PostgreSQL 5543, Redis 5544. `.env` не коммитится, содержит индивидуальные случайные локальные secrets; в нём для host-run используются 127.0.0.1 и соответствующие порты. Старый вариант Compose без overlay сохраняет внутренние порты контейнеров.

Проверено: Django check, отсутствие новых несозданных миграций, 55 pytest-тестов, Ruff. Браузер: все 30 экранов без JS pageerror, переход главная → товар, таблица размеров и переход корзина → адрес; desktop/mobile evidence в docs/project/visuals/django-*. Мобильная главная сохраняет правило: одна карточка и край следующей, горизонтально листаются товары.

Visual lint: исправлены вертикальный overflow заголовка, слишком мелкие налоговые подписи и контраст футера. Горизонтальный scroll #quick-buy-grid намеренный и соответствует требованию владельца; предупреждение локального Tailwind runtime принято только для development, production CSS ещё нужно собрать отдельно. Автоматический контраст прозрачного badge перепроверен и фон задан сплошным эквивалентом. Это не полная accessibility-сертификация всех исходных макетов.

Аналитика этапа: события не отправляются; операционные модели создаются только тестами/seed либо будущими явными командами. Новые необязательные SDK/cookies не добавляются. Для локальных demo-данных не используются реальные клиенты; очередь, секреты и production-данные не переносятся в preview.
