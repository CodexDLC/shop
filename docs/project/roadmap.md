# План разработки и приёмка

13.10.2026: foundation собран — Django, независимый engine, отдельный ARQ, зависимости/lock и local Docker. Проверены тесты, сборки, PostgreSQL migrations и задача через Redis/ARQ. Каталог и commerce-функции ниже ещё запланированы. См. [запуск](foundation-run.md).

Для каждого этапа учитываем [технические требования безопасности и корректности](security-and-correctness.md). Там перечислены обязательные негативные сценарии для платежей, остатков, доступа, файлов и восстановления.

| Этап | Результат | Проверка готовности |
|---|---|---|
| 0. Входные данные | Пример eBay listings/вариантов, папок фото, правила остатков | Есть проверенное соответствие одной модели и нескольких цветов/размеров |
| 1. Scaffold | Django, Postgres, настройки, зависимости, базовый кабинет | Приложение стартует, миграции проходят, конфигурация воспроизводима |
| 2. Каталог | Товары/варианты, список и карточка | Цвет меняет фото, размер выбирает SKU, недоступный вариант обозначен |
| 3. Фото | Preview импорта, ручная проверка, веб-версии | Повтор не создаёт дублей; неопределённые файлы не привязаны произвольно |
| 4. Корзина и заказ | Заказ сайта, резервирование, снимок цен | Последнюю единицу нельзя зарезервировать двумя локальными заказами; резерв освобождается по правилам |
| 5. Оплата | Один sandbox-provider и письма | Повтор webhook не меняет заказ дважды; возврат со страницы оплаты сам по себе не подтверждает оплату |
| 6. eBay | Read-only сопоставление, затем запись остатков и сверка | Нет пересоздания listings; старое чтение не затирает ожидающее обновление; ошибки видны |
| 7. Подготовка запуска | Доставка, юридические тексты, домен, backups/monitoring | Подтверждены реальные условия; выполнен пробный заказ и восстановление из backup |

Этапы оплаты/интеграций можно уточнить после входных данных. Объём и сроки оцениваем по проверенным контрактам, а не по наличию API в рекламном описании.

Значимые тесты: соответствие variant↔listing, конкурирующий локальный резерв, повтор событий, задержанное внешнее подтверждение, повтор импорта фото, обработка ошибки provider. Визуальная проверка карточки на desktop/mobile отдельно от backend-тестов.

Минимальный набор для демонстрации: 3 модели, несколько цветов/размеров, отсутствующий вариант, файл фото с неоднозначным соответствием. Проверяем повторный импорт и сохранение ручного порядка фотографий; для eBay — dry-run, пилотный SKU, повтор события и паузу синхронизации.
