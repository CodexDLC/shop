# Оплата: способы и провайдер

**Утверждено владельцем 15.10.2026: Stripe Checkout и PayPal через Stripe.** Один платёжный API для карт, PayPal, статусов и полных/частичных refunds; первоначально только sandbox. Прямой PayPal adapter не делаем в первой версии. Выбор не означает, что интеграция уже реализована или live разрешён. [Сравнение тарифов](payment-provider-comparison.md).

Обновлено 15.10.2026. Немецкий бизнес/Stripe account DE, расчёты EUR. PayPal обязателен; API провайдера международный, тарифы и доступность проверяем для Германии.

EHI в исследовании 2026 по данным 2025 указывает доли онлайн-оборота: PayPal 28,7%, Rechnung 26,1%, Lastschrift 14,4%, карты 13,7%. Это доли оборота панели исследования, не доли покупателей нашего магазина. [EHI 2026](https://www.ehi.org/presse/smartphone-statt-portemonnaie-mobile-payment-boomt/).

Первоначальный набор: PayPal + карты; покупка по счёту через подходящего провайдера — кандидат на следующий метод. SEPA/wallets добавляем по потребности. Собственное кредитование покупки по счёту не подразумевается.

Stripe поддерживает PayPal для аккаунтов DE. Для live потребуется активация бизнеса, связь Stripe с PayPal Business и выбор settlement: Stripe balance либо PayPal balance. Это один API магазина, но два коммерческих сервиса и соответствующие условия/аккаунты. [Активация](https://docs.stripe.com/payments/paypal/activate), [режимы получения денег](https://docs.stripe.com/payments/paypal/choose-settlement-preference).

Для первой версии используем **hosted Checkout**: корзина, адрес, доставка и обзор заказа на нашем сайте → страница оплаты Stripe → при выборе PayPal вход/подтверждение на PayPal → возврат к результату заказа. При оплате картой данные вводятся на Stripe, при необходимости подтверждение банка (3-D Secure). Следовательно, внешний переход нужен не только для подтверждения: hosted Checkout содержит платёжную форму целиком. Встраиваемые интерфейсы Stripe возможны позднее, не являются текущим выбором. [Варианты Checkout](https://docs.stripe.com/payments/checkout), [PayPal flow](https://docs.stripe.com/payments/paypal).

Сумму/состав заказа рассчитывает наш сервер; не предлагаем повторно вводить адрес, если он уже собран и может быть безопасно передан в выбранный Checkout flow. Success/return URL не доказывает оплату: подтверждение по проверенному webhook/сверке API. До подтверждения показываем ожидание, сохраняем заказ при закрытии вкладки или отмене. Юридическое оформление заключительного шага, итог/налоги/доставка и тексты кнопок проверяются для немецкого checkout по всему потоку.

Sandbox начинается после создания Stripe-аккаунта без завершения live-проверки бизнеса. Используем только test-ключи, тестовые webhooks и фиктивные данные; PayPal через Stripe имеет тестовую страницу Authorize/Fail. Production-аккаунты и допуск методов проверяются отдельно. [Sandbox](https://docs.stripe.com/get-started/account/set-up), [PayPal test flow](https://docs.stripe.com/payments/paypal/accept-a-payment?payment-ui=direct-api).

Движок проектируется с независимым PaymentGateway contract; официальный Python SDK `stripe` — только в адаптере. Django подключает адаптер, ARQ использует независимый контракт. Provider-specific статусы нормализуются на границе. Возврат денег — только после подтверждения сотрудником, с идемпотентностью и сверкой неизвестного исхода. Mollie и прямой PayPal сохранены в сравнении как альтернативы, не текущий план реализации.
