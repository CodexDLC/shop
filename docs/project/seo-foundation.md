# SEO-каркас магазина

Контракт21.10.2026. Реализация и доказательства проверки фиксируются в [задаче](../../tasks/active/2026-10-21-seo-foundation.md). Это технический каркас, не разрешение на публикацию магазина.

## Границы

SEO — Django web adapter: метаданные страницы, URL, middleware и XML/robots. В независимый codex_ecommerce и ARQ не добавляются импорты Django или логика шаблонов. Существующие серверные HTML-композиции сохраняются. Этот исходный каркас сам по себе не включал редактор текстов. Последующее развитие кабинета описано в [рабочем разделе SEO](seo-workspace.md); запуск индексации по-прежнему требует отдельного решения.

Origin настраивается явно; адреса canonical/OpenGraph/JSON-LD не строятся из Host, пользовательского поиска, return URL или токена заказа. Без доверенного origin canonical, og:url и JSON-LD отсутствуют, а индексация закрыта. Безопасный внешний og:image может использовать уже известный URL фотографии. Блоки head определены прямо в base.html, не внутри include; child templates не должны добавлять второй title/description/canonical.

## Политика страниц

- Local/staging/preview остаются закрытыми. Будущий публичный режим требует явного включения и корректного HTTPS origin. Существующая защита стенда Nginx/Basic Auth/noindex не меняется.
- Аккаунты, кабинет, корзина, оформление, персональные подтверждения, admin/staff, интеграции/API и preview/error routes не индексируются. Чувствительные значения не участвуют в canonical/OG/schema.
- Поиск, технические фасеты и сортировка: noindex, канонический адрес чистого каталога. Для чистой пагинации — адрес фактически отображаемой страницы; страница1 без лишнего параметра. Не создаём SEO-лендинги из каждой комбинации фильтров.
- Цвет и размер остаются вариантами одной модели. Параметры выбора не создают отдельные индексируемые страницы.
- В sitemap только разрешённые чистые страницы, никаких поисковых/персональных URL или prototype mobile aliases. Закрытый sitemap пустой. Товары требуют активной модели с опубликованной датой и EUR-вариантом без активного DEMO- SKU и других seed-маркеров demo; отсутствие остатков само по себе не основание выкидывать существующую модель. Текущим demo-товарам даты не присваиваем.

## Данные и языки

JSON-LD использует только отображаемые сведения: Product/BreadcrumbList и при наличии реального результата — summary approved отзывов. Нулевые/вымышленные оценки и отзывы не добавляются. Demo price/demo_quantity не являются рабочим Offer, наличие и условия доставки не выдумываются. Полноценные merchant rich results требуют реальных offers, остатков и утверждённых условий — это следующий этап.

Текущий русский маршрут использует немецкий fallback и не считается опубликованным переводом. Поэтому наличие языка в Django LANGUAGES не включает автоматически RU hreflang/sitemap. Публикация нового языка потребует готовых UI и товарных переводов, взаимных alternate ссылок и проверки соответствия страниц. x-default не создаётся как фиктивная языковая версия.

SEO-каркас не добавляет cookies, tracking SDK, внешнюю отправку метаданных или новые записи пользователей. Операционных сроков хранения не появляется: используются уже существующие товарные/публичные данные, временные метаданные ответа и настройки. Search Console, рекламные SDK и отправка sitemap наружу отдельно не подключаются.

## Источники правил

- [Google: варианты товара](https://developers.google.com/search/docs/appearance/structured-data/product-variants) — единый canonical для модели с вариантами на одной странице.
- [Google: robots meta и X-Robots-Tag](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) — robots.txt запрещает обход, но не заменяет noindex. Запрещённую к обходу страницу робот не читает; Basic Auth остаётся отдельной границей доступа стенда.
- [Google: языковые версии](https://developers.google.com/search/docs/specialty/international/localized-versions) — alternate для настоящих локализованных версий, не просто объявленных языков приложения.

## Следующие этапы

Редактируемые SEO-тексты/изображения и выбранный production domain, проверка реальных товарных данных/offer policy, полная локализация, отдельные содержательные категории/брендовые landing pages при подтверждённой потребности. Технический каркас не гарантирует позиции в поиске и не отменяет закрытие тестового стенда.

## Настройки и интеграция

Точки входа: `web.seo.origin`, `policy`, `metadata`, `structured_data`, `sitemap_products`, `views`, `SeoMiddleware`, `seo_context`, именованные маршруты `robots` и `sitemap` в корневом urls. Реальные head блоки: title, meta_description, meta_robots, canonical, hreflang, og_tags, extra_head_schema. `page_head` остаётся для прежних assets, не для второй копии SEO-тегов.

Настройки Django (не переменные окружения с автоматическим чтением):

| Настройка | Текущее значение/назначение |
|---|---|
| SEO_SITE_NAME | Männermasche |
| SEO_INDEXING_ENABLED | False по умолчанию |
| SEO_PUBLIC_ORIGIN | Пусто, production domain не выбран |
| SEO_FORCE_NOINDEX | True в local/preview/staging; публичный флаг его не обходит |

Origin принимает чистый публичный HTTPS-домен без credentials/path/query/fragment и нестандартного порта. Без origin в текущем локальном ответе нет canonical/og:url/JSON-LD: это намеренное отсутствие выдуманного production URL, не использование localhost в качестве канонического магазина. Сам title/description/robots/OG text формируется и без origin.

`robots.txt` закрытого режима отвечает Disallow: /. `sitemap.xml` — пустым urlset. Будущий разрешённый режим отдаёт чистые home/catalog/brands и опубликованные не-demо модели. Страница sitemap ограничена1000 товаров; при большем наборе выдаётся sitemapindex со ссылками на страницы, верхняя граница10000 частей. Запросы с неверным номером страницы/посторонними параметрами отвергаются. Не материализуется весь каталог или все варианты в Python.

Публичный robots не блокирует чтение noindex у служебных страниц; запреты обхода для некоторых технических параметров не являются защитой доступа. Существующие X-Robots-Tag ограничения сохраняются, включая noarchive; явный noindex у non-HTML API сохраняется без изменения прежнего формата заголовка. Legal hub-дубликат /rechtliches/ закрыт как alias; отдельные документы имеют собственные метаданные.

Общий механизм `codex-django` SEO был проверен: StaticPageSeo требует конкретную модель/Redis, а BaseSitemap автоматически публикует все LANGUAGES/alternates. Сейчас нужен ограниченный проектный policy поверх штатных Django ORM/Paginator/escaping, без параллельного CMS или нового cache слоя.

Исторический неактивный DEMO- SKU не блокирует модель с опубликованной датой и активным реальным EUR SKU, если нет demo tag/description marker. Витрина и sitemap используют один критерий активности. Offers всё равно отсутствуют, пока не подключены реальные цены/остатки. Существующие товары/даты/артикулы этим шагом не изменены.
