# План развития существующего кабинета магазина

Дата22.10.2026. Кабинет уже создан: общий вход/MFA, codex-django shell, меню/настройки/быстрый доступ, товары и варианты. Мы расширяем его, не строим второй кабинет. За основу берутся [первоначальный план](staff-cabinet-plan.md) и фактическая реализация. Этот документ — очередь самостоятельных поручений, не разрешение выполнить все этапы сразу.

Все последующие staff-экраны сразу делаются на русском и немецком; интерфейс проверяется на обоих языках, товарные данные локализуются отдельно.

Для каждого задания: MD с требованиями → тесты новой логики → реализация → целевые/связанные проверки → браузер для UI → независимый ревизор по выбранному режиму → результат и ограничения. Следующий этап начинается по отдельному поручению пользователя. Внешние оплаты/eBay/DHL/S3/SMTP/live-публикация остаются вне этой очереди.

- K3: «Делаем K3: локальный импорт каталога и фото с предварительной проверкой и безопасным повтором, с ревизором».
- K4: «Делаем K4: локальный склад и резервы, без синхронизации eBay, с ревизором».
- K5: «Делаем K5: обработка тестовых заказов сотрудниками и журнал действий, без оплат и DHL, с ревизором».
- K6: «Делаем K6: outbox, отдельный ARQ и письмо тестового заказа в Mailpit, с ревизором».
- K7: «Делаем K7: очередь обращений в кабинете и тестовые ответы через Mailpit, с ревизором».

Порядок можно менять. Приоритет K4 перед K5 нужен, если в обработке заказов уже требуется резерв; K7 можно делать независимо. Объём импорта определяется образцом реальных файлов, не предположением о структуре30ГБ фотографий.

## Границы K1

Сначала сохраняется немецкий контент модели обычными полями ProductInformation; UI остаётся переводимым по ключам. Размерная сетка относится к бренду/категории, её массовое редактирование — K2. Фото загружаются локально через storage; пакетный импорт — K3. Редактируемые независимые живые/черновые версии товара без снятия с витрины — отдельное возможное расширение, не обещание K1.

Публикация товара означает видимость в локальной витрине, а не включение SEO-индексации/реальных продаж. Текущий стенд закрыт. Доступы публикации проверяются отдельным разрешением; наличие staff-меню не заменяет проверку endpoint. Коммит/push/deploy не входят в завершение этапа без поручения.
