# Характеристики, размерные таблицы и основа отзывов

Реализация 20.10.2026: шаг2 [общей задачи витрины](../../tasks/active/2026-10-20-storefront-remaining.md). Дизайн PDP сохранён; данные макета заменены ORM-контентом. Миграция catalog.0004 создаёт четыре новые таблицы и ограничения, не наполняет существующие товары и не переносит примерные оценки/мерки в базу.

## Что заполнять

- `ProductInformation`: товар, language_code (например de), description/composition/care/fit/origin/certification. Одна запись на язык и товар. Обычный текст, не HTML. PDP выбирает запрошенный язык, затем немецкий; язык fallback обозначается. Пустые поля показываются как неподтверждённые сведения. У производителя артикул хранится в существующем Product.manufacturer_article.
- `SizeGuide`: бренд, необязательная категория, title, источник source_label/source_url, instructions. По умолчанию draft. Для публикации нужен источник. Таблица для конкретной категории приоритетнее общей таблицы бренда; чужая марка/категория не используется.
- `SizeGuideRow`: таблица, size, position, нижняя/верхняя границы waist/hip в cm. У каждой указанной мерки обе границы обязательны, положительны и упорядочены; нужна хотя бы одна мерка. Размер уникален в таблице. Все строки таблицы выводятся; это не остатки SKU. Inch вычисляются через Decimal/2.54 с округлением до одного знака, без повторного округления исходных cm.
- `ProductReview`: товар, rating1–5, отдельное публичное author_display, body и status pending/approved/rejected. По умолчанию pending. Auth email/адреса автоматически не подставляются. Публичны только approved; count/average учитывают все approved, список показывает10 последних. Нет галочки «проверенная покупка», публичной формы отправки, писем или рассылок.

Модели зарегистрированы в стандартном Django admin с обычными model permissions. Это не разработка нового рабочего кабинета и не расширение прав. Заполнять характеристики, сертификаты и мерки следует по подтверждённым данным производителя. Сам флаг публикации не проверяет достоверность источника. Не создавать отзывы от имени покупателей; модель предназначена для будущей модерируемой системы.

## Интерфейс и границы

`ProductDetailView` → `product_information_context()` → catalog/includes/product_information.html и size_guide.html. Вкладки description/material/delivery/reviews работают с клавиатурой и прямыми hash-ссылками. Size guide — native dialog: modal focus, Escape/close с возвратом к кнопке; cm/inch меняют только единицы. Выбранный в товаре размер помечается в таблице; сама таблица не меняет SKU и не обещает доступность. На мобильном таблица имеет внутреннюю горизонтальную прокрутку, содержимое окна — вертикальную.

Удалены прежние inline handlers и preview-скрытие #sizeGuideModal; это замена макета, не второй конкурирующий механизм. Прямой hash #sizeGuideModal сохранён. Без JS секции информации доступны полностью; увеличение/размерный dialog требуют JS. Галерея шага1, мини-карточки и механизм выбора SKU сохраняются.

Дополнительные запросы выполняются только на PDP: информация1, таблица1, строки1 при наличии таблицы, агрегат отзывов1, список1. Всего HTTP PDP9 без таблицы /10 с таблицей; контекст фичи4/5. Home5 без изменений; исторический listing context10 с шагом3 стал12 за счёт двух новых фасетов (см. catalog-listing.md). Количество SQL не растёт на каждую строку/отзыв; это не обещание измеренной production latency. Размерные строки не обрезаются, отзывы ограничены10. Источники выводятся только HTTP(S), весь редакционный контент экранируется.

## Данные и проверки

Новые трекеры, cookies, аналитические очереди и передача событий не добавлены. Чтение сведений/таблиц/отзывов не создаёт записи. Публичный сбор отзывов выключен; перед его включением нужны политика хранения/удаления, основания обработки и модерация. Общие access logs и существующие внешние фото/шрифты не менялись; наличие этого этапа не означает готовый consent manager.

На текущей локальной базе нет подтверждённых характеристик/таблиц/отзывов: интерфейс показывает честные пустые состояния. Для тестов используются изолированная БД и отдельно помеченный HTML-fixture, без записи примерных мерок в магазин. Реальные отзывы/состав/мерки через eBay или API не импортируются этим этапом.

Проверки: test_product_information_context/page/behavior.py, tests/js/product-information.cjs, query budgets PDP/home; браузер desktop/390px и независимая ревизия. Итоговые результаты и замечания — в задаче шага2. Соседние рекомендательные карточки PDP пока остаются помеченными демонстрационными блоками и не становятся реальными характеристиками этого товара.
