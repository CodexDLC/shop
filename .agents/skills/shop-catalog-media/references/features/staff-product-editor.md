# Staff-редактор товара

Статус 22.10.2026: реализован локальный редактор, контракт и границы — [документ](../../../../../docs/project/staff-product-editor.md); очередь будущих заданий — [K1–K8](../../../../../docs/project/staff-cabinet-roadmap.md).

- Сохранять существующий codex-django staff shell и формы. Общая модель, варианты, характеристики, фото, проверка/публикация — отдельные вкладки. Таблицы размеров принадлежат справочнику бренда/категории, не копировать их в товар.
- Новая модель всегда draft/inactive. Published нельзя редактировать до явного withdraw с предупреждением о снятии с витрины. Не менять существующую видимость на GET/при миграции. Параллельных live/draft редакций пока нет.
- Все записи держат parent Product select_for_update, проверяют подписанный снимок, права модели и CSRF. mark_changed сбрасывает review; publish требует отдельного publish_product и актуального fingerprint содержимого. Изменение справочника/переведённого legacy-описания тоже должно делать старую проверку неактуальной. Дубли и stale — без повторной операции.
- Готовность: описание, базовые поля, активный EUR SKU с положительной ценой, фото для каждого активного цвета либо общая галерея. Demo_quantity не означает реальный склад. Публикация не включает индексацию тестового стенда.
- Фото — Django storage, проверка фактических байтов Pillow и ограничений, безопасное перекодирование под новым UUID; SVG/анимация не принимаются. public_url объединяет новый file и legacy image_url, alt_text имеет legacy fallback. Размеры одного цвета делят галерею. Старые объекты при замене/удалении связи физически не удаляются; GC требует отдельного решения. Не загружать внешние URL автоматически.
- Main/variant/information/image model admin readonly: не открывать обход процесса публикации. Private preview требует staff permissions, private/no-store и noindex; покупка в preview выключена.
- Проверки: tests/web/test_staff_publication.py, test_staff_product_media.py, test_staff_product_edit.py, test_staff_variants.py; public gallery/information/SEO regressions. SQLite-тесты и UI не доказывают конкурентную работу PostgreSQL.

S3, импорт и реальный склад — будущие отдельные задачи. Общие справочники и категории уже имеют локальные редакторы; действующие границы описаны в docs/project/staff-workspace.md. Новые внешние операции этот reference не разрешает.

Все staff-фичи сразу имеют русский и немецкий интерфейс: полное покрытие staff.* в messages/ru.json/de.json с одинаковыми параметрами и скомпилированными PO/MO. Ссылки/POST redirects сохраняют locale. Рабочие маршруты RU `/ru/staff/`, DE `/staff/`; переключатель Django set_language POST+CSRF. Проверять test_staff_localization.py и browser на обоих языках. Язык редактора не меняет язык данных товара, readiness и fingerprint немецкого контента.

Категории (C1): отдельный редактор дерева/DE-RU контента/фото/порядка/видимости, добавочная миграция0008 без перегруппировки. Slug существующей категории сохраняется. Назначение товара только через K1 черновик. Структура/видимость опубликованной ветки требуют publish_product и явного подтверждения; контент редактируется отдельно и входит в fingerprint. Category admin readonly. Эффективная видимость наследуется от родителей во всех публичных selectors; сохранять querybudget и параметризованный recursive CTE, не вводить N+1. Проверки: test_category_management.py и listing/SEO/header/cart/publication regressions. Предпросмотр показывает сохранённое состояние, не обещать unsaved preview/bulk assignment.
